FDA 0.5.5 / ARM10 — reported inline inventory, hero binding and per-colour HP

Установка: весь архив в НОВУЮ папку, build.bat с MSVC x64/C++/Windows SDK.
Маркер ARM10 в build.bat и меню. При ошибке не использовать старую DLL.
Первичная проверка в демо/локальном лобби. В папку установленной игры ничего не копировать.

Что показал последний лог:
controller найден, source=2; runtime RTTI parsed=94; confirmed=1 — настройка уже сделана.
localFrame=0 означает срыв последующей привязки/валидации, а не отсутствие контроллера.
raw0: low32=25, high32 выглядит как первый handle; raw8=FFFFFFFFFFFFFFFF — два пустых handle.
Это соответствует кандидату count+0/inline handles+4, а НЕ pointer-at-8.

Inventory:
Добавлен layout=3: count строго 25, 25 встроенных uint32 handles сразу после count (+4).
Область заканчивается до schema m_bItemQueried (+0x88): +0x20+4+25*4=0x88.
Не сканируется произвольная память. Сохраняются старые два валидируемых layouts.
Обязательный inventory parent должен равняться full entity handle героя.
Каждый непустой handle должен разрешиться с полным serial и item backlink; torn parity,
parent, count и изменение любого inline slot отвергаются. Весь список перечитывается.
Layout=0/Read=0 остаётся неизвестным снимком; items=0 не трактуется как отсутствие предметов.
По вашим raw словам новый путь основан на конкретной структуре; полное live подтверждение
всех 25 slots здесь невозможно. Нужно получить inventoryLayout=3 и inventoryRead=1 в Dota.

Привязка своего героя:
Контроллер не заменяется произвольным Huskar. Assigned hero full handle/local flag,
RTTI/scene/life/team/clock и выделение по-прежнему проверяются.
Добавлено независимое доказательство владения через schema Hero::m_iPlayerID.
Если NPC owner=-1/не прочитан, но dedicated hero player ID валиден и совпадает с controller
player ID, это может подтвердить собственность в демо. Любой валидный конфликт двух ID
отвергается. Значения вне допустимого диапазона кроме -1 также отвергаются.
Это НЕ утверждение, что именно owner=-1 был причиной вашего localFrame=0: старый отчёт
не содержал frameGate и assigned/owner/player полей.
В ARM10 Copy Armlet diagnostics добавлены bind: frameGate, mask, assigned/hero pointer,
local flag, controller player ID, NPC owner и Hero player ID; identity[] для наблюдаемых героев.
Если localFrame всё ещё 0, эта строка даст конкретную следующую точку проверки.

HP:
Общий X/Y остаётся общим; дополнительный сдвиг красного/вражеского бара независим.
HeroInfo -> Доп. сдвиг HP красного бара (вниз +), default +6px.
Не трогать свой уже настроенный общий Y для исправления врага; менять только новый slider.
При переносе в новую папку нужно сохранить/повторить своё прежнее значение общего Y.
При подтверждённом local frame красный определяется относительно local team; до этого
только для UI используется читаемый controller team, иначе группы Radiant/Dire.
Этот display-only путь НЕ назначает локальную команду для автоматизации.
Сброс сдвигов: общий X/Y=0, дополнительный красный=6. Штатные бары не рисуются/не изменяются.
По скриншоту +6px является начальной калибровкой, не универсальным точным HUD rect.
Реальное положение штатного бара из Panorama не извлекается; привязка в Dota не проверена.

Armlet:
После загрузки проверить свой слот/клавишу и подтверждение (при запуске оно сбрасывается).
Включить модуль; выделить только собственного Huskar; закрыть меню на 2–3s, снова открыть
Huskar -> Копировать диагностику Armlet -> прислать ARM10 отчёт.
Ожидаются localFrame=1, inventoryRead=1; inline layout=3.
Если модуль заблокирован, не выбирать произвольного героя и не отключать проверки.
Ограничения ARM9 сохранены: порог HP, восстановление, пауза 2s; не incoming-hit predictor,
не off/on за один server tick. Опасный DoT/неизвестные данные/фокус/пауза блокируют.
При сбое Armlet может остаться OFF; проверить вручную. Не гарантия выживания.
