FDA 0.5.5 / HUD5 — HeroInfo, без Custom hero bars и боксов героя

Установка:
Закрыть Dota и программу, использующую старую DLL. Распаковать ВЕСЬ архив в новую папку.
Запустить build.bat (MSVC x64, Desktop development with C++, Windows SDK).
Успешный результат build\obsdota2.dll. При ошибке не использовать старую DLL.
Маркер меню FDA 0.5.5 / HUD5. Сначала проверить в демо/локальном лобби.
Исходники, НЕ готовая DLL. Ничего не копировать в установленную папку игры.

Что изменено:
- Custom hero bars удалён из рендера, конфигурации и меню.
- Боксы/угловые рамки героев не вызываются ни в обычном, ни в observed-only режиме.
- HP — число поверх штатного бара; отдельный кастомный бар НЕ создаётся.
  Якорь берётся из мировой позиции health-bar offset. Если число смещено относительно
  реального бара, HeroInfo -> Сдвиг числа HP по X / Y. Положение в живой Dota не проверено.
- Бейдж уровня героя НЕ создаётся. Способности с уровнем и сегментами; активные предметы
  в отдельных строках. Заряды показываются только когда положительные, не 0 на каждом мече.
- Статусы STUN / HEX / SILENCE / MUTE / ROOT / DISARM — по прочитанным unit-state bits.
  ILLUSION — по проверенному флагу или идентифицированному модификатору, не по одинаковой модели.
  До трёх явных статусов и +N для остальных, чтобы не раздувать панель.
- При прочитанном инвизе — круг, INVIS, обводка и семь секунд с момента обнаружения.
  Это отсчёт наблюдения, НЕ фактическая длительность способности и НЕ предсказание раскрытия.
  После семи секунд герой не объявляется видимым: маркер сохраняется при положительном инвизе.
  При пропадании данных/камеры и последующем новом наблюдении отсчёт может начаться заново.
- Баффы/дебаффы рисуются возле каждого героя. Flask/Tango/Clarity с именем/иконкой и временем
  из идентифицированного модификатора. Наличие бутылки в инвентаре НЕ означает активную Flask.
- Проверка пересечения размещаемых строк, ограничение экраном, компактные иконки,
  обводка текста. Старое отдельное debug-окно Active Effects убрано, эффекты inline.

Чтение HeroInfo:
Предметы, способности, статусы и модификаторы больше не отключаются из-за отсутствия
локального контроллера. Для модификаторов используется отдельно проверенное время героя.
Observed-only остаётся ok=false/localHandle=0 и НЕ запускает автоматизацию.
Совпадение всех контейнеров с реальным клиентом здесь не подтверждено.
Неизвестный инвентарь не выдаётся за пустой. Нет выдуманных предметов/баффов/кулдаунов.
При неоднозначном count/capacity, если все валидированные положительные снимки одинаковы,
их эффекты разрешено показать (buffVisual=1), но полный список НЕ подтверждён (buffsRead=0).
Для Armlet и других автоматических действий это всё ещё блокировка.
При переходе со старого профиля новые HeroInfo-флаги включены; далее настройки сохраняются.

Armlet Huskar:
- Исправлен обязательный второй бинд: можно включить переключателем меню, бинд необязателен.
- Silence/disarm больше не трактуются как запрет использования предмета (mute).
  Mute/stun/hex/command restriction/out-of-game и опасные/неизвестные состояния блокируют цикл.
- Добавлен ограниченный поиск ссылок на контроллер в writable/non-executable данных client.dll.
  16K слотов за проход scanner thread, до 16MiB, без виртуальных вызовов и сканирования всей кучи.
  Учитываются все просмотренные кандидаты, local flag, назначенный handle и владелец героя,
  повторные чтения и уникальность. Неполный/неоднозначный поиск НЕ включает автоматизацию.
- Это дополнительный путь поиска, а НЕ подтверждённый фикс локального игрока в вашем клиенте.
- Для проверки: свой Huskar, реальный слот Armlet, его нативная клавиша, подтверждение после
  проверки в демо, закрытое меню, фокус Dota, один выбранный герой, проверенные инвентарь/баффы.
- На вашем скриншоте подтверждение было OFF, активационный бинд не задан, localFrame отсутствовал.
- Модуль — HP threshold, НЕ предсказатель входящих ударов/снарядов и не гарантия выживания.
  При потере фокуса/сбое цикл не воспроизводится поздно; Armlet может остаться OFF: проверить вручную.

Если что-то не отображается/Armlet заблокирован:
Data diagnostics -> Copy ESP diagnostics -> прислать весь HUD5-отчёт (hero[], data[], refs).
Особенно localFrame/source, refsStage/slots/hits, inventoryRead/items/abilities,
buffsRead/buffVisual/buffs, clockRead, illusionRead, stateRead и текст статуса Armlet.
Refs stage: 1 заголовки/секции недоступны; 2 поиск; 3 не найден; 4 подтверждён;
5 неоднозначно; 6 лимит не позволил закончить полный поиск. Source=4 — найден через ссылки,
даже если controllers из entity scanner остаётся 0. Первый полный проход может занять ~30 секунд.
НЕ включать автонажатия выбором произвольного героя по экрану и не обходить подтверждение.
