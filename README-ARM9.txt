FDA 0.5.5 / ARM9 — runtime RTTI, inventory и повторное переключение

Изменены именно читатели/логика, а не только меню. Нет гарантии работы в живой Dota:
нужен следующий runtime-отчёт, а не подстановка чужого Huskar в local player.

1. RTTI:
ClassOf сначала читает MSVC CompleteObjectLocator/TypeDescriptor из памяти загруженного
client.dll, а не выбирает класс по старой таблице RVA. Проверяются границы image,
signature=1, self RVA, primary vtable offset, type/hierarchy RVAs, окончание и формат имени.
Текущий C_DOTAGamerules НЕ принимается за контроллер даже на старом controller RVA.
Кэш защищён mutex, лимит 4096 положительных имён. Отрицательные миллионы адресов не кэшируются.
В ARM9-отчёте runtime RTTI attempts/parsed. Если RTTI отсутствует, старый путь остаётся:
это НЕ динамический schema resolver всех полей и НЕ обещание совместимости с любым патчем.
Чтение только памяти процесса; нет скачивания PDB, новых движковых вызовов и файлов игры.

2. Inventory:
Проверяются два положения C_NetworkUtlVectorBase: count+0/data+8 и data+0/count+8.
Для нового data-first пути обязателен inventory parent с полным handle данного героя
(schema field m_hInventoryParent +0xA8). Каждый не пустой handle должен разрешаться,
item backlink/полный serial проверяются. Неоднозначные разные снимки отвергаются.
Count <=27, данные/parent/parity перечитываются, весь проход имеет один исходный parity.
Частичный/порванный снимок не разрешает Armlet. Неизвестные предметы не выдаются за Armlet.
inventoryLayout=1 старый count-first, 2 data-first, 0 нет подтверждённого снимка,
-1 разные валидированные варианты конфликтуют. raw0/raw8/parent/probeMask для проверки.
Это ограниченная проверка двух layouts, не доказательство универсального контейнера Dota.

3. Выделение:
Проверяется singleton CUtlVector<CEntityIndex> count+0/data+8 и size+16/data+0.
Allocator capacity НЕ используется вместо size. Повторные чтения count/data/index.
Выбранный индекс должен совпасть с уже подтверждённым собственным Huskar.

4. Повторный цикл:
После подтверждённого ON и успешного восстановления HP модуль снова готов к следующему
циклу. Раньше armed мог оставаться false, пока HP не поднялось выше threshold+100.
Минимальная пауза 2s, наблюдение реального OFF перед ON, проверки восстановления и Fault
сохранены. Это не слепой double tap и не переключение off/on в один серверный тик.

Установка/проверка:
Закрыть старую программу/игру, весь архив в новую папку, build.bat с MSVC x64 и SDK.
Маркер ARM9 и в build.bat, и в меню. При ошибке не пользоваться старой DLL.
Только демо/локальное лобби. В Dota проверить вручную клавишу Armlet выбранного слота.
Поставить подтверждение после проверки: оно сбрасывается при запуске/смене настройки.
В вашем логе confirmed=0; новая версия НЕ включает эту галочку молча.
Включить модуль; выделить только собственного Huskar; закрыть меню.
Для полного прохода ссылки на контроллер могут понадобиться ~30s.
После этого открыть Huskar -> Копировать диагностику Armlet -> прислать весь ARM9-текст.
Ожидаются localFrame=1, controller не 0, inventoryRead=1, confirmed=1.
Если не так, RTTI parsed и raw inventory поля дадут конкретную следующую точку проверки.

Ограничения:
Локальный игрок определяется только подтверждённым контроллером, local flag, assigned
hero и owner. Текущий список объектов/глобальные ссылки могут не найти его в вашем билде.
Не добавлен произвольный heap scan/выбор первого героя/назначение localFrame вручную.
DoT/Burning Spear DEBUFF, неизвестные данные/пауза/фокус/выделение по-прежнему блокируют.
Порог HP, не предсказание ударов/снарядов/DoT и не полноценный универсальный Armlet abuse.
При сбое Armlet может остаться OFF; проверить вручную, затем сбросить цикл.
Нет обещания выживания. Рендер HUD8 сохранён, косметика GC выключена.
