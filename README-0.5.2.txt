FDA 0.5.2 — УВЕДОМЛЕНИЯ КАРТЫ И КОНСЕРВАТИВНОЕ ДОБИВАНИЕ
Полный исходный проект, не готовая проверенная DLL.

ДОБАВЛЕНО В КОД
Карта > Map notifications (ПКМ или ЛКМ открывает настройки):
- «Обнаружена руна»: прочитана сущность руны или поменялся её тип. Не означает,
  что руна появилась именно сейчас. Первое наблюдение после подключения молчит.
- «Спавн руны: данные клиента»: увеличился m_flLastSpawnTime уже отслеживаемого
  спавнера, событие не старше 2 секунд по используемому игровому времени.
  Это свидетельство из клиентской сущности, не подтверждение сервера.
- Напоминание за 3–30 секунд (10 по умолчанию) по m_flNextSpawnTime. Не использует
  устаревшие расписания патчей, не утверждает появление или наличие руны.
  Обратный отсчёт обновляется; после срока напоминание исчезает.
- Для будущей случайной руны усиления тип не угадывается; вода определяется
  отдельным полем спавнера. Богатство/мудрость используют класс спавнера.
- Обнаруженный вражеский вард (OFF по умолчанию): только прочитанная сущность,
  живой вард и установленный бит видимости своей команды. Исчезновение не
  означает уничтожение. Расшифровка маски по текущему клиенту ещё требует проверки.
- Рошан: только изменения жив/мёртв у отслеживаемой прочитанной сущности.
  Исчезновение из списка не считается смертью. Первое обнаружение молчит.
- Координаты x/y, до 4 сообщений, до 6 секунд на экране. Без отправки сообщений
  союзникам, изменения игры, аудио и восстановления данных за туманом войны.
- Старые события подавляются после смены матча, повторного включения, отката
  времени и разрыва валидных кадров >5 секунд. Видимость не создаёт повторов
  для того же handle. Точные серийные номера различают переиспользованные слоты.
- Русские и английские тексты, параметры сохраняются в существующем INI.

Бой > Last-Hit:
- «Минимальный урон вместо среднего» ON по умолчанию.
- Нижняя оценка физического урона по DamageMin/Max/Bonus и броне, округление вниз.
- Если данные урона/брони не прочитаны или невалидны, lethal-маркер не выставляется.
- Убрано искусственное прибавление 75 к дальности атаки в lethal-классификации.
- Не учитывает специальные модификаторы, серверное время, полёт снаряда, других
  атакующих, блок/иммунитет. Это НЕ гарантия last-hit/deny при 1 HP.
- Auto-attack creeps — отдельная прежняя функция и не блокируется этими проверками.

ИСПРАВЛЕНО
EntityByHandle больше не разрешает устаревший серийный номер через совпадение
индекса. Неудачное точное разрешение возвращает 0. Это НЕ заявление «ESP починен».
Руны/спавнеры не обязаны иметь NPC HP, поэтому читаются отдельной веткой FillUnit.
Назначение m_flRuneTime не установлено схемой; оно НЕ используется как время спавна.

ЧТО НЕ ЗАКРЫТО
- Active Flask / Tango / Clarity: нет проверенного чтения списка модификаторов.
- Kill Stealer: нет реализации; универсальная имитация нажатия по низким HP не добавлена.
- Auto-accept: отключён; найденный protobuf ReadyUp требует настоящего fresh key,
  источник такого ключа в данном адаптере не установлен. Не используются guessed RVAs.
- Полноценное уклонение по траекториям, сведения о скрытых противниках/смоках/
  фарме леса, гарантированное добивание: не реализованы этим изменением.
- Skin Changer остаётся экспериментальным кодом 0.5.1. Арсенал и модели в матче
  не проверены; 283 cosmetic definitions пока display-only. README-0.5.1.txt — фон.
- Видимость косметики только у тебя и отсутствие санкций не подтверждены.

ПРОВЕРКИ
- ASan/UBSan: portable tracker — baseline, dedup, pause, rollback, re-enable,
  match changes, serial handles, invalid fields, rune reminder and Roshan cases.
- ASan/UBSan: физический диапазон урона, границы lethal, броня, неизвестные данные.
- Actual game.cpp с MOCK-памятью: Classify/FillUnit/EntityByHandle, руны без HP,
  случайный будущий тип не угадывается, invalid fields, recycled handle rejection,
  нижняя/средняя оценка и неизвестный урон в интеграции.
- Старые cosmetic core и adapter regression-тесты прошли; в том числе 6000
  malformed-wire cases. Используется MOCK Steam, не настоящий Steam.
- Реальный ImGui отрисован на Linux-стенде; просмотрены настройки уведомлений
  1920x1080/800x600, обновлённый Last-Hit и уведомления.
- MSVC, Windows, настоящий Steam и живая Dota здесь НЕ тестировались.
- Используемое время унаследовано из simulation/animation time локального героя.
  Если оно перестало обновляться, расчётные уведомления тоже останавливаются.
- Существующая инициализация entity system/ESP не исправлялась. Если кадр невалиден,
  client.dll отличается или сущность не доступна, уведомлений может не быть.

СБОРКА
Распаковать весь архив в новую папку, MSVC x64 + Windows SDK, запустить build.bat.
build.bat удаляет старую DLL перед компиляцией и при ошибке не оставляет её как новую.
Сначала проверять в демо/локальном лобби, не воспринимать эту версию как проверенную
для сетевого матча или безопасную от банов. Не заменять steam_api64.dll.
Portable tests: tests\run-events-tests.bat из Native Tools Command Prompt.
Linux MOCK tests: python3 tests/run-events-tests.py (g++ с ASan/UBSan).
Cosmetics tests: tests\run-cosmetics-tests.bat.
