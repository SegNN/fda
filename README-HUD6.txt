FDA 0.5.5 / HUD6 — стабильные ряды и круглые эффекты

Установка:
Закрыть программу/игру, использующую старую DLL. Распаковать весь архив в новую папку.
build.bat: MSVC x64, Desktop development with C++, Windows SDK.
Результат build\obsdota2.dll. При ошибке не использовать старый бинарник.
Маркер меню HUD6. Сначала демо/локальное лобби. Ничего не копировать в папку игры.

Рендер:
- Убрано межгеройное переразмещение: раньше алгоритм коллизий переносил строки вверх.
  Теперь способности всегда под ногами своего героя (foot + 12px), затем предметы и эффекты.
  Пересечение двух близких героев НЕ переносит строки. Они могут перекрываться:
  это намеренная стабильность, не обещание отсутствия любых пересечений.
  У края экрана ряд обрезается viewport, а не телепортируется наверх/вбок.
- Способности: квадратные иконки, затем сегменты максимального уровня.
  Изученные сегменты светлые, пустые тёмные. Числа уровня не рисуются.
  Неизученные способности затемнены. Цифры cooldown остаются внутри изученной иконки.
  Неизвестный maxLevel не подменяется выдуманным количеством сегментов.
- Баффы/дебаффы: круглые текстуры с круглой маской, обводка remaining/duration,
  секунды по центру (округление вверх). До восьми эффектов в строке.
  Времена только из прочитанных модификаторов. Неизвестный таймер = ?, не выдуманный отсчёт.
  Flask/Tango/Clarity зелёные; несколько явно известных DoT красные;
  неизвестная полярность нейтральная. НЕ заявляется универсальное определение всех дебаффов.
  Иконка ищется среди ресурсов проекта по имени модификатора/способности.
  Если подходящего ресурса нет, показывается ?, не ложная иконка другого эффекта.
- HP: только текст, штатный бар игры не изменяется. Поднят на 8px относительно HUD5,
  центрирование по ширине текста и проектируемому anchor, координаты округлены до пикселя.
  Отдельный шрифт MuseoSansEx 500 из ресурсов исходного проекта, не UI SF Pro Semibold.
  X/Y калибровка в HeroInfo остаётся. Точная привязка к штатному бару в живой Dota не проверена.
- Никаких дополнительных HP-баров, уровней героя или рамок героя.
  Проверки данных HUD5, observed-only без автоматизации, 7s observation INVIS сохранены.

Armlet — как настроить:
1. Демо, именно ваш Huskar. Armlet в одном активном слоте 1–6, не в рюкзаке.
2. В настройках Huskar указать этот слот и РЕАЛЬНУЮ клавишу предмета из Dota.
   Номер слота НЕ равен клавише: слот 1 может быть Z, 1 или другой настройкой.
   Поддерживается одиночная буква/цифра без Ctrl/Alt/Shift.
3. Проверить этой клавишей ручное выключение/включение Armlet в демо.
4. Включить «Клавиша проверена в демо; риск понятен» и модуль.
   Подтверждение сбрасывается при запуске/смене профиля/слота/клавиши и в некоторых сбоях.
   Верхний бинд необязателен; можно включать переключателем меню.
   Если задан hold-бинд, он должен удерживаться и не совпадать с клавишей предмета/меню.
5. Выделить ТОЛЬКО своего Huskar, закрыть меню, вернуть фокус Dota, отпустить клавиши.
6. Начать с HP выше порога (например, 350). Статус «Готов: жду HP ниже порога».
   Ниже порога модуль пытается цикл OFF -> подтверждение OFF -> ON,
   проверяет восстановление, минимальная пауза между циклами 2 секунды.

Если не работает:
Не обходить проверки. Теперь основные причины отображаются в меню по-русски.
localFrame=0: локальный игрок не определён, настройки это не исправят.
inventoryRead=0 или buffsRead=0: данные не подтверждены, даже если ESP показывает иконки.
buffVisual=1 НЕ означает buffsRead=1: положительные эффекты можно отрисовать,
но отсутствие опасных эффектов для автоматизации не установлено.
Прислать ТОЧНЫЙ статус из меню Huskar и весь Data diagnostics -> Copy ESP diagnostics (HUD6).
Нужны localFrame/source/refsStage/slots/hits, data[] и buffsRead/inventoryRead.
Состояния mute/stun/hex, опасный DoT, неизвестные данные, фокус/пауза/выделение блокируют цикл.
Модуль не предсказывает входящие удары и не гарантирует выживания. При остановке Armlet
может остаться OFF: проверить вручную и затем сбросить цикл.
Исполнитель Armlet и поиск локального игрока не объявляются исправленными для живого клиента:
в HUD6 улучшены объяснения блокировок, а НЕ отключены защитные проверки.
