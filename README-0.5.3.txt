FDA 0.5.3 — ЭФФЕКТЫ, РУЧНОЙ KILL STEALER, КАЛИБРУЕМЫЙ AUTO-ACCEPT
Полный исходный проект. Это экспериментальная реализация, НЕ подтверждённая
сборка для живой Dota. Не заявляется, что «все функции теперь готовы».

ЭФФЕКТЫ
Прочее > Active Buffs / Debuffs. По умолчанию включено, только временные.
Панель слева показывает доступного героя под курсором; иначе своего героя.
Flask, Tango, Clarity имеют короткие подписи. Остальные прочитанные модификаторы
показываются внутренними именами без modifier_. Для всех — стаки, прочитанный
остаток времени или явная отметка «время неизвестно»/«постоянный».
Наличие предмета в инвентаре не создаёт «активный эффект».

Читатель проверяет имя, клиентский RTTI, полный handle владельца, index/serial,
диапазоны времени/стаков и повторный снимок списка. Не вызывает методы движка.
Перебирается только непрозрачный префикс manager (0x00..0x27), а не произвольная
память. Возможные count/data пары — гипотезы контейнеров, НЕ заявленные оффсеты.
Layout принимается только после проверки всех элементов непустого массива и
при отсутствии неоднозначности count/capacity. Неизвестный пустой список НЕ
считается «баффов нет». При невозможности проверки показывается «список недоступен».
256 элементов максимум; панель показывает до 12, с ограничением по высоте и
счётчиком остальных. Без иконок/полной локализации всех имён и без разделения
неизвестных модификаторов на бафф/дебафф. Это общий читатель, не жёсткий список 3.
Список может временно быть недоступен при перестройке контейнера или несовместимой
версии клиента. Pending-deletion flags не интерпретируются по непроверенным offsets.
Диагностика: Modifier lists verified / unknown и количество прочитанных эффектов.

KILL STEALER — РУЧНОЙ ПРОФИЛЬ ОДНОГО СПЕЛЛА, НЕ УНИВЕРСАЛЬНЫЙ ДЛЯ ВСЕХ ГЕРОЕВ
Бой > Kill Stealer. OFF по умолчанию. Нет угаданных таблиц урона для 100+ героев.
Настрой в демо:
1. Выбери своего героя и нажми «Привязать профиль к текущему герою».
2. Задай фактический слот способности (0 — первый) и её клавишу.
3. Задай урон до сопротивления, тип Magical/Physical/Pure, фактическую дальность
   и запас HP. Проверь значения после уровней/талантов/улучшений.
4. Включи quickcast НА НАЖАТИЕ в самой Dota для этой кнопки и только после этого
   включи «Quickcast на нажатие подтверждён» в модуле. Normal cast/key-up не поддержаны.
5. Кнопкой «Клавиша» назначь ОТДЕЛЬНЫЙ бинд удержания, не совпадающий со спеллом.
6. Включи модуль и сохрани профиль. Закрой меню, держи бинд для действия.

Проверяются: герой привязки, отдельное включение, физическое удержание бинда,
фокус окна данного процесса, закрытое меню, видимость своей команды, отсутствие
инвиза/иллюзии, прочитанные списки эффектов, состояния героя/цели, мана, level,
activated, phase, raw cooldown, mute/frozen/indefinite flags и координаты внутри
client area. Изменение героя блокирует действие до новой привязки.
Учтены базовые физическая броня/магическое сопротивление. Состояния иммунитета,
нетаргетируемости и набор защитных эффектов (Linken, Lotus/Counterspell,
Grave/BorrowedTime/FalsePromise/Aeon/Reincarnation и др.) консервативно блокируют.
Из подходящих целей выбирается герой с меньшим HP. Не чаще одного ввода за 1.2 с.
Обычный Windows SendInput: переместить курсор и нажать/отпустить кнопку quickcast.
Нормальный cast и автоматический щелчок по цели не эмулируются. Курсор не
возвращается мгновенно, иначе движок может получить другое положение мыши.

Это НЕ гарантия убийства. Не моделируются полёт снаряда, канал/кастпоинт,
все специальные защиты/амплификация/условия урона, вложенные способности,
фактическое попадание и серверная задержка. Профиль не обновляется автоматически
при смене уровня/талантов. Не использовать для channel/skillshot/условных/charge spells.
При неизвестных данных функция не действует. Базовые поля/маски и cooldown всё
ещё требуют подтверждения в живой Dota. При выключенном module бинд его не включает.

AUTO-ACCEPT — ШТАТНАЯ КНОПКА С ДВУМЯ ПРОВЕРКАМИ
Настройки > Auto-accept. OFF по умолчанию.
1. Включи, закрой меню. При НАСТОЯЩЕМ приглашении наведи курсор в центр текста
   «Принять» и нажми F8. Не назначай F8 другим функциям; это калибровка. Нужен свежий сигнал GC. Сохраняется область 160x40.
2. Первое приглашение прими вручную. Его калибровка НЕ вызывает click.
3. Следующее: Dota в фокусе, тот же размер client area/язык/вид кнопки.
   Модуль наводит курсор на сохранённое место, сравнивает 3 кадра через 250 мс,
   повторно проверяет изображение/фокус и один раз нажимает обычную кнопку.
4. При смене разрешения/темы/языка либо несовпадении образца повтори F8.
   «Удалить образец кнопки» удаляет accept-button.bin рядом с DLL.

Сигнал: только настоящий incoming GC ReadyUpStatus 7170, корректный protobuf
конверт, один fixed64 lobby_id и local_ready_state=UNDECLARED (поле 6=0 или
документированное значение по умолчанию protobuf при отсутствии поля 6).
Повторные/неподтверждённые поля, stale >8 с, unfocused window,
открытое меню, валидный match frame, чёрный/одноцветный capture или несовпадение —
без клика. Значение по умолчанию взято из proto-схемы, но само по себе не вызывает click: 
обязательны свежий пакет и подтверждение изображения. До 64 последних
приглашений защищены от повторного click. Raw capture нигде не отправляется.
Нет guessed ReadyUp key, private RVAs, фонового клика или обхода проверки доступа.
Accepted-состояние сообщается только если его прислал GC после попытки/калибровки;
сам SendInput не считается подтверждением принятия. Не гарантируется отсутствие
санкций/блокировок очереди. Может не работать с эксклюзивным fullscreen/чёрным GDI.

ПРОВЕРЕНО ЗДЕСЬ
ASan/UBSan portable: buff reader, kill core, accept gate/image matcher, runes/damage.
Production game.cpp с MOCK-памятью: ReadBuffs/владелец/Flask/serial mismatch и
прежние rune/handle/damage cases.
Production auto_accept.cpp с MOCK Windows/GDI/GC: запись образца, 3 кадра, один
click, пропуск unfocused/size-changed/capture-failed/in-match.
Production kill_stealer.cpp с MOCK input: профиль, hero lock, quickcast confirmation,
баффы, иммунитет, throttle. Это проверка логики, не настоящая очередь матчей.
Cosmetic regression: core incl 6000 malformed-wire inputs; adapter с observer stub.
Реальный ImGui на Linux-стенде: новые меню, compact states и mock effects HUD.
НЕ ПРОВЕРЕНО: MSVC/Windows ABI, реальный GDI/SendInput, настоящий Steam/GC,
расположение списка модификаторов в живом клиенте, cooldown semantics,
точное targeting/resistance поведение, реальная автоматизация, отсутствие банов.

реальный Арсенал и модели в матче не подтверждены. Скрытые серверные события,
полноценный dodge/skillshot model и гарантированное добивание не добавлены.
