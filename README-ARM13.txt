ARM13 — завершение включения Armlet при появлении DoT

Это накопительный ПАТЧ поверх полного ARM10, ARM11 или ARM12, НЕ полный проект.
Закройте игру и старую DLL. Распакуйте ZIP в корень проекта с заменой файлов.
Запустите build.bat. Только после успешной сборки используйте новую DLL.
Маркер сборки и диагностики: ARM13. Установленные файлы Dota не изменяются.
GitHub не обновлён. Исправления HP/selection и self-модификатора из ARM11/12 сохранены.

Изменения:
1. Распознанный DoT больше не отменяет уже начатый OFF -> подтверждение OFF -> ON.
2. Если Armlet уже выключен и HP ниже порога, включение не блокируется только из-за DoT.
3. Новый OFF при распознанном DoT всё ещё запрещён, потому что времени следующего тика
   и его урона модуль НЕ знает. Эта версия НЕ делает полноценный abuse под любым уроном.
4. Первая причина Fault сохраняется до сброса и не затирается открытым меню/смертью.
   cycle: phase / firstFault; faultContext: time / hero / hp / phaseBefore / observedOn.
   observedOn=-1 означает, что проверка остановилась ДО чтения текущего toggle.
   phase: 0 Idle, 1 WaitOff, 2 WaitOn, 3 Recover, 4 Fault.
   Контекст Fault — кадр обнаружения сбоя, не журнал смертельного урона.
5. Сохранены ограничения выделения своего героя, focus, item identity, readiness,
   живого героя и читаемых данных. Эти проверки могут остановить ON: нельзя обещать
   автоматическое восстановление после потери фокуса, смерти или неизвестного предмета.

Не изменены: ожидание OFF минимум 100 мс, timeout 700 мс, проверка восстановления HP
1 секунда, пауза между циклами 2 секунды. Не предсказываются атаки/снаряды/тики.
Не гарантируются выживание, ON в один server tick или работа в любых обстоятельствах.

Проверять сначала в демо. После сбоя копируйте ПОЛНЫЙ отчёт ARM13 Armlet ДО сброса
цикла: firstFault/faultContext/selection/danger. В ARM12 посмертный лог причины смерти
не содержит; эта версия не добавляет полноценный combat log.

Тесты на искусственной памяти и Windows-вызовах: точный modifier_viper_poison_attack_slow
после OFF и падение HP не отменяют ON; начальное OFF под Viper допускает ON;
новый OFF под Viper запрещён; первая причина Fault не затирается открытым меню.
Все локальные mock/portable тесты прошли без ASan/UBSan. Полная сборка MSVC/Windows,
реальная Dota и серверная задержка НЕ проверены.
